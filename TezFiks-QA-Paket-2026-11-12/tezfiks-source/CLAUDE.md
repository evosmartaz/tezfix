# TezFiks

On-demand handyman marketplace for Baku (then Azerbaijan, then worldwide). Customers request a handyman ("usta");
solo handymen or company ("park") members accept, travel, fix, and get paid. Android first, iOS later.

- **Spec (business rules are authoritative here):** `docs/superpowers/specs/2026-10-24-tezfiks-design.md`
- **Build plan (waves, lanes, conventions):** `docs/superpowers/plans/2026-10-25-tezfiks-build-plan.md`
- **Design boards:** `design/01..06-*.png` (brand: primary #00A971, dark #0B1B2B, accent #F59E0B, bg #F6F8FA, danger #E5484D, font Inter)
- **Shared contract (single source of truth for every endpoint and payload):** `packages/shared/src/contract/**`, socket events in `packages/shared/src/socket.ts`

## Core business rules (short form; spec wins on conflict)

- Platform fee: flat 10 AZN held from the provider's prepaid wallet on accept, captured when the 5-min free-cancel window closes (or at completion,
  if sooner); decline on arrival refunds it. Wallet must hold >= 10 AZN to accept. The platform never prices work.
- The handyman enters the final price (labour + materials). Payment is cash or in-app (test-mode only in the demo). Only in-app gets the free re-fix guarantee and the tip page.
- Free cancel for both sides within 5 min of acceptance. Decline on arrival: the provider's 10 AZN is refunded; the customer pays 15 AZN (10 to the provider, 5 to the platform).
- Emergency requests: +5 AZN per handyman, paid by the customer. A customer may request several handymen (slots).
- Dispatch uses H3 rings (res 7) that widen over time. Companies also get a list-style dispatch board. Company workers see only location and the customer's name and photo.
- Chat and phone numbers unlock when the handyman is about 5 min away. Names and photos are always visible. Phones never appear in offers, lists or push payloads.
- Solo handymen: ID + face check, pending until admin approval. Companies add members via invite links; managers assign jobs (phone or web).
- Login by phone OTP over a WhatsApp bot (no SMS). Languages: az (default), ru, en.
- Demo only: admins can top up balances; payments are test-mode.

## Rules every change must follow

- **Tests are the specification. Never weaken, delete or edit an assertion to make it pass; fix the code.** Change a test only when it contradicts the spec, and say so explicitly.
- Money is integer qəpik (BigInt in the DB), never floats. Every balance change goes through `LedgerService` (double-entry, holds, idempotency keys; a DB trigger enforces zero-sum and append-only).
- Business time comes from `Clock` (`this.clock.now()`), never `new Date()`/`Date.now()`, so tests can move time.
- No hard-coded user-facing strings: use `packages/i18n` (server: `I18nService.t(locale, 'server.<module>.<key>')`).
- The contract is additive only: you may add optional fields or new endpoints, never rename or remove. Rebuild shared afterwards.
- API handlers: `@Controller()` with no path; `@Route(api.x.y)` + `@Input() input: RouteInput<typeof api.x.y>`; responses must match the contract exactly
  (tests run with `CONTRACT_VALIDATE_RESPONSES=true`; nullable fields present as `null`). Errors: `throw new ApiException('<CODE>')` with codes from `packages/shared/src/errors.ts`.
- Atomic work: `inTx(prisma, async (tx) => ...)`, row locks with `SELECT ... FOR UPDATE`, state transitions as conditional `updateMany` and check `count`.
- Timers: `JobsService.schedule` plus a `ReconcilerService` repair task; every handler is idempotent. Tests use `JOBS_MODE=manual`: `t.clock.advance(ms)`, then `t.jobs.runDue()` / `t.reconciler.tickAll()`.
- Admin mutations call `AuditService.log(...)`. Realtime emits go through `RealtimeService` (recorded in tests: `t.realtime.sentTo(room, event)`).
- Foundation core (`apps/api/src/{config,infra,common}`, `modules/ledger`, `test/helpers`, `prisma/schema.prisma`, migrations) changes only deliberately, never as a side effect of a feature.
- After every multi-step money test: `ledger.globalSum() === 0n` and `verifyIntegrity()` returns `[]`.

Full conventions (decorators, helpers, factories, Redis/test DB numbering): plan section "Conventions (API lanes)".

## Tooling quirks on this machine (Windows 11, Git Bash + PowerShell)

1. **GateGuard hook**: blocks the first Bash command of a session and the first Write/Edit of each new file until you state the facts
   (the request, the file's purpose and callers, that no existing file covers it, the user's instruction verbatim). State them in text and retry the same call.
2. **rtk hook corrupts heredocs that contain non-ASCII** (ə ı ş ü, Cyrillic). Write such files with the Write tool, or write one bundle and run `node scripts/unbundle.mjs <bundle>`.
3. **npm 11 blocks install scripts.** Install only with `node scripts/npm-safe.mjs install -w <ws> <pkg>@<exact> --save-exact`; approve scripts only for well-known packages (see root `allowScripts`).
4. Port 3000 may already be used by an unrelated local app; check before starting the API (or set `PORT`).
5. Other Docker projects run on this machine (`bexsh-ish-*`, `konstruktor`). Only touch the `tezfiks-dev-*` containers.
