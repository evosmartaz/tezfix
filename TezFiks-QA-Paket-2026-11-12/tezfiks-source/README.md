# TezFiks

**On-demand handymen for Baku.** A customer asks for a handyman ("usta"); nearby solo handymen or company teams get the
offer, one accepts, drives over with live tracking, fixes the problem, enters the final price, and gets paid in cash or
in the app. Android first (iOS later), in Azerbaijani, Russian and English.

| Live (demo) | URL |
|---|---|
| API | https://evosmart.az/tezfix/api (health: `/tezfix/api/health`) |
| TezFiks admin panel | https://tezfiks.evosmart.az (also https://evosmart.az/tezfix/admin) |
| Company panel and dispatch board | https://tezfiks.evosmart.az/tezfix/company |
| Company invite links | `https://evosmart.az/tezfix/join/<token>` |
| Android APKs (download page) | https://tezfiks.evosmart.az/download/ |

Demo accounts (phones, roles, OTP code) are listed in [docs/demo.md](docs/demo.md).

## What is inside

| App | Package | For whom |
|---|---|---|
| **TezFiks** (`apps/customer`) | `az.tezfiks.app` | Customers: request a handyman (now, emergency or scheduled; one or several), search by category or by photo, live tracking, chat, pay cash or in-app, tip, rate, re-fix guarantee, business accounts with B2B quote projects. |
| **TezFiks Usta** (`apps/pro`) | `az.tezfiks.usta` | Handymen: onboarding with ID + face check, go online, offers with a countdown, navigation, price entry, earnings and payouts, wallet top-up. Company managers accept and assign jobs from the phone; company workers see a limited view. |
| **Panels** (`apps/panel`) | web, `/tezfix/*` | TezFiks admins (dashboard, KYC review, handymen, companies, customers, requests, cases, projects, invoices, payments, payouts, categories, settings, audit log, live map, demo console) and company admins (orders, dispatch board, workers, invites, projects, balance, settings). |
| **API** (`apps/api`) | Docker image | REST + Socket.IO + background jobs, base path `/tezfix/api`. |

## How it works (short version; the spec is authoritative)

- **Platform fee:** a flat 10 AZN is held from the handyman's prepaid wallet when they accept (they need at least 10 AZN).
  It is captured when the 5-minute free-cancel window closes or at completion, and refunded on a decline at arrival.
  The platform never prices the work: the handyman enters labour + materials and the customer confirms.
- **Cancellations:** free for both sides within 5 minutes of acceptance. Declining on arrival costs the customer 15 AZN
  (10 to the handyman, 5 to the platform). Emergency requests cost +5 AZN per handyman.
- **Dispatch:** H3 rings (resolution 7) that widen over time; companies also get a list-style dispatch board.
- **Live tracking:** from the moment a handyman accepts (scheduled jobs: from an hour before the start), the customer sees
  their position on the map and an ETA that updates on its own from the live position and the route.
- **Privacy:** names and photos are always visible; chat and phone numbers unlock only when the handyman is about
  5 minutes away (by that live ETA). Phones never appear in offers, lists or push payloads.
- **Trust:** solo handymen pass an ID + selfie check and wait for admin approval; companies add members by invite link.
- **Login:** phone number + one-time code delivered over WhatsApp (no SMS provider).
- **Money** is integer qəpik in a double-entry ledger with holds and idempotency keys; a database trigger keeps every
  transaction balanced and the ledger append-only.

## Repository layout

npm 11 workspaces, Node >= 24, TypeScript 6.

| Path | What |
|---|---|
| `packages/shared` | The contract: every endpoint and payload as zod 4 schemas, socket events, enums, money/phone/time/geo helpers, business policies, typed API client. |
| `packages/i18n` | Translations (`az`, `ru`, `en`) for the apps, panels and server messages. |
| `packages/mobile` | Code shared by both apps: API client, auth, socket, maps, UI kit, theme, auth screens. |
| `apps/api` | NestJS 12, Prisma 7 (PostgreSQL 17), Redis 8 (BullMQ jobs, Socket.IO). |
| `apps/customer`, `apps/pro` | Expo SDK 58 / React Native 0.88 apps (expo-router). `android/` is generated by `expo prebuild` and not committed. |
| `apps/panel` | Next.js 16 panels with a BFF under `/tezfix/bff/*`. |
| `deploy/` | Production Docker Compose, nginx snippet, local dev databases. |
| `docs/` | Spec, build plan, wave handoff notes, [deployment runbook](docs/deploy.md), [demo guide](docs/demo.md). |

## Run it locally

Prerequisites: Node 24+, npm 11, Docker Desktop. For the Android apps also JDK 17 and the Android SDK (an emulator or a phone).

```bash
npm ci                                   # npm 11 runs install scripts only for packages approved in package.json (allowScripts)
npm run build:shared                     # build the shared contract (again after every change in packages/shared)
npm run dev:db                           # PostgreSQL on 127.0.0.1:55432, Redis on 127.0.0.1:56379

cd apps/api
cp .env.example .env                     # local settings (DEMO_MODE, OTP code echo, dev JWT secret)
npm run prisma:generate
npx prisma migrate deploy
npm run seed                             # categories, platform accounts, first admin (ADMIN_BOOTSTRAP_EMAIL / _PASSWORD)
DEMO_MODE=true npm run seed:demo         # optional demo data and logins (docs/demo.md)
npm run dev                              # API on http://localhost:3000/tezfix/api (set PORT to change it)
```

Panels (in another terminal):

```bash
cp apps/panel/.env.example apps/panel/.env.local   # API_INTERNAL_URL / NEXT_PUBLIC_SOCKET_URL point at the local API
npm run dev -w @tezfiks/panel                      # http://localhost:3100/tezfix/admin
```

Mobile apps on an Android emulator (the emulator reaches your computer at `10.0.2.2`):

```bash
cd apps/customer                                   # or apps/pro
EXPO_PUBLIC_API_URL=http://10.0.2.2:3000/tezfix/api npm run android
```

Logging in locally: with `OTP_DEV_ECHO=true` (the default in `apps/api/.env.example`) the app shows the code; the demo phones
also accept the bypass code from `OTP_BYPASS_CODE`.

## Tests

The tests are the specification: a failing test means the code is wrong, not the test.

```bash
cd apps/api && TEST_DB_NAME=tezfiks_test_int TEST_REDIS_DB=12 npx vitest run    # API, each run uses its own database
npm test -w @tezfiks/shared && npm test -w @tezfiks/i18n
npm test -w @tezfiks/mobile && npm test -w @tezfiks/customer && npm test -w @tezfiks/pro
npm test -w @tezfiks/panel
```

About 1 960 tests in total (API 692, panel 423, customer app 383, pro app 222, mobile 201, shared 34, i18n 5).
The API suite checks every response against the contract and that every contract endpoint is implemented.

On a phone emulator, [e2e/maestro](e2e/maestro/README.md) has Maestro tours of both apps, and `e2e/run-screen-sizes.sh`
runs them on five screen sizes (small 720x1280, standard, large font, tall 1440x3120, short 1080x1920) with screenshots.

## Build the Android apps for production

The API address is baked in at build time. For each app:

```bash
cd apps/customer                                      # or apps/pro
export EXPO_PUBLIC_API_URL=https://evosmart.az/tezfix/api
export EXPO_PUBLIC_MAPBOX_TOKEN=pk....                # map tiles (Mapbox public token; see "Status" below)
export GOOGLE_MAPS_ANDROID_KEY=...                    # alternative to Mapbox: Google map
export TEZFIKS_RELEASE_STORE_FILE=...                 # + _STORE_PASSWORD, _KEY_ALIAS, _KEY_PASSWORD: docs/android-release-signing.md
npx expo prebuild --platform android --clean          # always --clean: Gradle does not notice changed EXPO_PUBLIC_* values
cd android && ./gradlew assembleRelease               # APK: android/app/build/outputs/apk/release/app-release.apk
```

Release builds are signed with the company release key and fail without it (BUG-003). Key creation, backup, signature
checks and the Google Maps key setup: [docs/android-release-signing.md](docs/android-release-signing.md).

## Deployment

The live stack runs on the evosmart.az server with Docker Compose in `/opt/tezfiks` behind the host's nginx and Cloudflare:
API on `127.0.0.1:3300`, panels on `127.0.0.1:3310`, PostgreSQL and Redis on the Docker network. Secrets live only in
`/opt/tezfiks/deploy/.env` on the server. The full runbook (first deploy, nginx, Cloudflare, backups, moving the database to
Supabase) is [docs/deploy.md](docs/deploy.md).

Updating the live server from a checkout of this repo:

```bash
git archive --format=tar.gz HEAD | ssh root@<server> 'tar -xzf - -C /opt/tezfiks'
ssh root@<server> 'cd /opt/tezfiks && docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build'
```

`up -d --build` rebuilds the images, runs the database migrations (the one-shot `migrate` service) and restarts the API
and panels. Take a database backup first (runbook section 3).

## Status and what is still needed

Built: everything in the spec for the demo, including the admin and company panels, the bot simulator for live demos and
the demo seed. Deployed at the URLs above.

Before real users:

- **Leave demo mode:** set `DEMO_MODE=false` and remove `OTP_BYPASS_*` in `deploy/.env`. Outside demo mode the API
  refuses to start with a bypass code, a weak `JWT_SECRET` or fake payments. It also turns off test card payments and
  admin balance top-ups (cash still works) and the demo bots, and it accepts "arrived" only when the handyman's live
  position is within `arrivalMaxDistanceM` (admin settings, default 500 m) of the address.
- **Admin accounts:** there is no second login factor yet. Use long unique passwords and give the OPERATOR role (not
  ADMIN) to staff who do not need settings or money.
- **WhatsApp login codes:** the server runs with `OTP_CHANNEL=console`, so only the demo phones (bypass code) can log in.
  Real logins need Meta WhatsApp Cloud API credentials (`OTP_CHANNEL=whatsapp_cloud` + `WHATSAPP_*`) or your own bot
  (`OTP_CHANNEL=webhook`).
- **Maps:** the base map is, first match wins, Mapbox raster tiles (Static Tiles API) when a Mapbox **public** token is
  set, the Google map when a Google key is set, otherwise OpenStreetMap tiles (fine for development, not for production
  traffic). Apps: `EXPO_PUBLIC_MAPBOX_TOKEN` (or `GOOGLE_MAPS_ANDROID_KEY`, restricted to `az.tezfiks.app` and
  `az.tezfiks.usta`) at build time; panel: `NEXT_PUBLIC_MAPBOX_TOKEN` (or `NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_KEY`) at image
  build time. Optional `*_MAPBOX_STYLE` picks a Mapbox Studio style. A secret `sk.*` token fails the build. Without a
  payment method the Mapbox account is usage-limited (tiles stop at the limit). Address search and traffic-aware ETAs
  still use `GOOGLE_MAPS_SERVER_KEY`.
- **Payments:** in-app payments are test-mode only (a TezFiks checkout page, no real money). A real payment provider and the
  legal setup for holding customer money are still to do.
- **Push notifications:** `PUSH_PROVIDER=log`; offers still arrive over the socket while the app is open. Real pushes need a
  Firebase project (`google-services.json`, `PUSH_PROVIDER=fcm`).
- **Find by photo:** needs `ANTHROPIC_API_KEY`; without it the feature is hidden.
- **iOS** builds are not set up yet.
